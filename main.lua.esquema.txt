Especificación Técnica Detallada del Dashboard y Sistema de Llaves
1. Estructura de la Base de Datos en Firebase (JSON Schema)
La base de datos en tiempo real de Firebase (Realtime Database) almacenará dos nodos principales: system_status (para controlar variables globales como el mantenimiento) y keys (donde reside cada llave generada).
{
  "system_status": {
    "vip_paused": false,
    "paused_at": 0
  },
  "keys": {
    "KEY-VIP-98F1A2": {
      "type": "VIP",
      "user": "ChrissPlayer",
      "created_at": 1786400000,
      "expires_at": 1788992000,
      "remaining_seconds": 2592000,
      "hwid_limit": 2,
      "used_hwids": [
        "RobloxHWID-8823-1102-AAAA"
      ],
      "status": "active"
    },
    "KEY-FREE-31B99C": {
      "type": "FREE",
      "user": "N/A",
      "created_at": 1786400000,
      "expires_at": 1786418000,
      "remaining_seconds": 18000,
      "hwid_limit": 1,
      "used_hwids": [],
      "status": "active"
    }
  }
}

Parámetros del Nodo keys:
 * type: "VIP" o "FREE".
 * user: Nombre asignado al cliente en llaves VIP. En llaves FREE se establece automáticamente como "N/A".
 * created_at: Marca de tiempo en segundos (Unix Timestamp) de la creación de la llave.
 * expires_at: Marca de tiempo exacta en que la llave dejará de funcionar (created_at + duración_en_segundos).
 * remaining_seconds: Almacena el tiempo disponible en segundos. Se utiliza activamente cuando el sistema entra en modo pausa.
 * hwid_limit: Entero que define el límite de dispositivos permitidos (1, 2 o 3).
 * used_hwids: Arreglo de cadenas de texto con los identificadores de hardware que han activado esta llave.
 * status: "active", "paused", o "expired".

3. Especificación de los Módulos del Panel
A. Barra de Navegación y Métricas
 * Indicador de Estado: Un badge dinámico en la esquina superior derecha que muestra 🟢 Sistema Operativo o 🟡 Mantenimiento VIP Activo.
 * Tarjetas de Contador (KPIs):
   * Total Activas: Suma de todas las llaves cuyo estado sea active.
   * Usuarios VIP: Conteo de registros donde type == "VIP".
   * Llaves FREE: Conteo de registros donde type == "FREE".
B. Generador VIP 💎
 * Entrada de Usuario: Campo obligatorio. Si el campo está vacío al presionar el botón, el borde resalta en rojo.
 * Selector de Duración:
   * 7 Días = 604,800 segundos.
   * 15 Días = 1,296,000 segundos.
   * 30 Días = 2,592,000 segundos.
 * Límite de HWID: Botones de opción única (Radio Buttons) con valores 1, 2 o 3.
 * Salida: Al generar, se crea una llave única con el prefijo KEY-VIP- seguido de 6 caracteres alfanuméricos aleatorios. Muestra una ventana emergente con la llave creada y un botón directo para copiarla al portapapeles.
C. Generador FREE 🎁
 * Entrada de Cantidad: Campo numérico (mínimo 1, máximo 500 por lote).
 * Selector de Duración:
   * 3 Horas = 10,800 segundos.
   * 5 Horas = 18,000 segundos.
   * 1 Día = 86,400 segundos.
 * Salida: Genera en bucle las llaves solicitadas con el prefijo KEY-FREE-. Al finalizar, despliega un cuadro de texto masivo (Textarea) con todas las llaves generadas separadas por saltos de línea, acompañado de un botón "Copiar Lote Completo".
D. Sistema de Pausa Global (VIP Maintenance)
Un botón conmutable (Toggle Switch) de alto impacto visual situado arriba de los generadores:
 * Estado NORMAL (Verde): El tiempo corre habitualmente para todos.
 * Estado PAUSADO (Naranja con parpadeo):
   * Envía una actualización a Firebase cambiando system_status/vip_paused a true.
   * Recorre todas las llaves en el nodo keys con type == "VIP".
   * Calcula los segundos restantes individuales: \text{remaining\_seconds} = \text{expires\_at} - \text{tiempo\_actual\_unix}.
   * Cambia el atributo status de esas llaves a "paused".
 * Reanudación: Al desmarcar el botón, el sistema toma el tiempo_actual_unix y recalcula la nueva fecha de expiración para cada VIP: \text{expires\_at} = \text{tiempo\_actual\_unix} + \text{remaining\_seconds}. Restablece el status a "active".
E. Tabla de Monitoreo y Kill Switch
 * Actualización en Vivo: Conectada a través de onValue de Firebase. Cualquier cambio en la base de datos refresca la tabla sin recargar la página web.
 * Filtros: Pestañas superiores en la tabla para filtrar por: Todas, Solo VIP, Solo Free.
 * Buscador: Barra de texto para filtrar en tiempo real por nombre de usuario o por la cadena de texto de la llave.
 * Columna Expiración:
   * Muestra un temporizador regresivo dinámico en formato DD:HH:MM:SS.
   * Si la llave está pausada, muestra la etiqueta ⏸️ PAUSADA (Tiempo Congelado).
 * Columna HWID: Muestra el contador actual respecto al límite (ejemplo: 1/2 Devices).
 * Acción Kill Switch (Eliminar): Un botón rojo con el icono de basurero en cada fila. Al presionar, abre una confirmación de seguridad. Al confirmar, ejecuta remove() en Firebase para esa llave específica.
4. Flujo de Verificación en el Script Lua (Roblox Client)
Cuando el jugador ingresa su llave en la interfaz de Roblox y presiona "Conectar", el código Lua ejecuta la siguiente secuencia lógica de validación remota mediante HttpService:
                    [ Usuario ingresa la Key en Roblox ]
                                     |
                         [ HttpService:GetAsync() ]
                                     |
                       ¿Existe la Key en Firebase?
                               /           \
                             NO             SÍ
                             /               \
                 [ Acceso Denegado ]     ¿Está el status en "paused"?
                                            /                  \
                                           SÍ                   NO
                                          /                      \
                        [ Error: "Script en          ¿Tiempo actual > expires_at?
                          mantenimiento,                /                  \
                          tiempo congelado" ]         SÍ                    NO
                                                     /                       \
                                         [ Key Expirada ]          ¿HWID registrado?
                                                                      /           \
                                                                    SÍ             NO
                                                                   /                 \
                                                       ¿Coincide con este    ¿HWIDs usados < límite?
                                                             player?           /                 \
                                                             /     \          SÍ                  NO
                                                           SÍ       NO         |                   |
                                                           |         |  [ Registrar HWID ] [ HWID Excedido ]
                                                           +----+----+         |                   |
                                                                |              |                   |
                                                                v              v                   v
                                                      [ EJECUTAR SCRIPT ]  [ PERMITIDO ]    [ BLOQUEADO ]

 * Consulta HTTP: Solicita los datos de la llave específica directamente al endpoint JSON de Firebase.
 * Pausado Global: Si la llave tiene status == "paused", detiene la ejecución y notifica en la interfaz del juego: "El script se encuentra en mantenimiento VIP. Tu tiempo está congelado y no se consumirá."
 * Expiración: Compara os.time() de Roblox contra expires_at. Si os.time() > expires_at, rechaza el acceso notificando "Llave expirada".
 * Validación HWID:
   * Obtiene el identificador único mediante game:GetService("RbxAnalyticsService"):GetClientId().
   * Si el HWID ya está en la lista used_hwids, permite el acceso.
   * Si es un HWID nuevo y el tamaño del arreglo used_hwids es menor que hwid_limit, agrega el nuevo HWID a Firebase vía HttpService:RequestAsync() con método PATCH y permite el acceso.
   * Si la lista de HWIDs ya alcanzó el hwid_limit y el identificador actual no coincide, bloquea la ejecución notificando "Límite de dispositivos alcanzado para esta llave".
